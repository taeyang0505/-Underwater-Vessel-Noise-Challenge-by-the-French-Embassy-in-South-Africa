# Underwater Vessel Noise R9: 로컬 검증과 Public LB 간극 진단 자문

아래는 2026-10-26 기준 실제 저장 예측·정답·학습 로그 및 사용자가 제공한 Zindi 제출 화면으로 확인한 상태입니다. 서버 접속 정보·계정·키·토큰·원시 관측 자료는 포함하지 않습니다. 공개 점수에 맞춘 보정 계수나 Test 분포에 맞춘 타깃 조정이 아니라, 물리 생성기·모델 특징·검증 설계의 문제를 분리할 진단 실험을 제안해 주세요.

## 1. 대회 Task와 정답

- 입력은 원시 WAV가 아니라, 15분 × 25개 주파수 대역의 dB 관측 행렬입니다. Test.csv는 1,500행, ID와 관측 375열입니다.
- 주 회귀 목표 share_added_vessel은 관측된 전체 혼합 에너지 중 알려진 추가 성분이 차지하는 비율입니다. Public Score는 1 − RMSE입니다.
- score_added_vessel은 추가 유무의 순위를 평가하는 진단 ROC-AUC용 출력입니다. 회귀 share와 별개로 해석해야 합니다.
- 제공된 남아공 배경에 자연 선박음이 이미 있어도, 인위적으로 추가한 성분이 없으면 이 Task의 share=0입니다. 자연 선박 탐지 정답과 동일하지 않습니다.
- B=배경, A=알려진 추가 성분, E=B+A, O=관측 마스크일 때:
  q=A/E, y=sum(O*A)/sum(O*E).
- 학습 입력은 0.1dB 격자로 반올림합니다. 정답 q/y는 원래 추가 성분으로 계산한 정밀도를 유지합니다. 모델 풀링 가중치 w는 반올림된 관측에서 계산합니다. 반올림으로 생기는 작은 풀링 차이는 별도 검증했지만, 이 사실이 실제 Test 생성기와의 완전한 일치를 보증하지는 않습니다.
- 비공개 Test 정답과 정확한 전체 생성기·추가 세기·혼합 연산자 분포는 확보하지 못했습니다.

동일한 제출 앙상블의 로컬 gate 대 Public 차이:
- RMSE: 0.038135235 → 0.217535806 (약5.70배)
- 진단 AUC: 0.944842846 → 0.555066666

### 3.4 이전 R5 실패의 참고값

이전 R5 CNN은 INNER 3,000건에서 RMSE0.090808147/AUC0.996720833이었지만 Public RMSE0.348008679/AUC0.539533333이었습니다. 최대100epoch/ES7 중26epoch 실행, best checkpoint19였습니다. R5와 R9는 데이터·타깃 분포·생성기가 달라 로컬 지표를 직접적인 모델 개선량으로 비교할 수 없습니다.

## 4. 현재 R9 데이터와 전처리

- 대회 남아공 원본1,715,779행을 25개 공통 대역의 15분 배경 창으로 정리했습니다.
- 원래 허용한100,965개 배경 창 중 경계 분만 NaN으로 마스킹하고 관측 최소3분 조건을 적용한100,964개를 R9 배경 pool로 사용합니다. 전체 공개 배경을 모두 재편입한 것은 아닙니다.
- 원천 background_group을 합성 전에5분할하고, 동일 센서 계열의 900초 support 사이에24시간 purge를 유지합니다. TRAIN과 평가 역할의 background_group/base_window 직접 중복은 없습니다.
- Fold0 TRAIN은78,869개 배경 원천을 매 epoch 정확히1회씩 순회하며 동적으로 합성합니다. 100epoch의 노출 횟수를 독립 원천 샘플 수로 세지 않습니다.
- 외부 참조는 보유한 VTUAD vessel 아카이브의509개 클립 전체를 사용합니다. WAV 헤더 기준 약33.16시간, 완전한 native 분은1,978분입니다. 전용 ambient16개는 별도 manifest에만 있고 이번 TRAIN 참조/음성에 실제로 들어가지 않았습니다.
- 509개 중 weak class가 background인22개도 vessel 아카이브 포함분으로 입장했습니다. 정답은 추가한 녹음 전체의 알려진 에너지이며, 이를 순수 분리 선박 에너지로 주장하지 않습니다. 이22개를 자동으로 오라벨이라고 단정할 수 없습니다.
- 모든 TRAIN·검증 역할에 같은509개 참조를 공유합니다. metadata hull/day 연결을 합친 전체 참조 그래프는1component이므로 참조 독립 CV가 아닙니다.
- 합성은100% minute-first: 2초 Hann PSD에서25대역 요약을 만든 뒤30개를 선형 평균하여 native 1분 행렬을 먼저 만듭니다. native_inside50%, 1~3분 short25%, edge-straddling25%, smooth EQ±6dB, 전체 native peak 기준SNR[-10,+10]dB를 사용합니다. 시간 warp·강제 fade·파형 반복·결측 보간은 없습니다.
- 입력은 상대8채널: 대역별 시간 median/q20/q05 차감, 인접 관측 분 차분, 저·중고대역 동조 특징, 창 내부 상대 spectral profile, 관측 mask, sqrt(w)입니다. db/100, q0, Bhat/E, site/recorder ID를 직접 특징으로 넣지 않습니다.
- 상대 profile과w는 주파수별 상대 스펙트럼 모양을 유지하므로 임의의 장비 주파수 응답 변화에 완전히 불변인 특징은 아닙니다.
- 네 신경망은 q_hat∈[0,1]을 예측하고 sum(w*q_hat)으로 share를 구합니다. LightGBM은 기존 상대 grid·통계·물리 특징3,827개로 share를 직접 회귀합니다.
- 신경망 진단 score는0.5*share와 중고대역 셀 mask 대비의 결합이며, LightGBM은0.5*share+0.5*별도 classifier 확률입니다. 실제 제출의 score는 이 member score를 동일한 앙상블 가중치로 합친 값입니다.

## 5. 이번 정리 과정에서 확인한 구체적인 검증 제약

### 5.1 사이트·녹음기 홀드아웃이 아님

Fold0 TRAIN 사이트는 Richards Bay45,969 / St Francis17,956 / St Croix10,132 / Durban2,496 / Bird Island1,872 / Cape Recife240 / Riy Banks204입니다. selection은 앞의5개 사이트만 포함하며, selection의7개 recorder 문자열은 전부 TRAIN에도 있습니다. fit/gate의 모든 사이트·recorder도 TRAIN에 있습니다. 그룹·시간 분리는 지켰지만 새 사이트/녹음기 검증은 아닙니다.

기존 calibration9,049개와 domain_holdout16,048개는 R9에 복구하지 않았습니다. domain의 Fish Hoek/Sea Point/Saldhana Bay 세 사이트는 현재 TRAIN에 없습니다. 이들은 대회가 공개한 배경으로 새로운 원천 홀드아웃 진단을 설계할 후보입니다. Test에는 공식 site/recorder 메타데이터가 없으므로, 과거 스펙트럼 프로브로 추정한 Test 사이트 비율을 확정된 사이트 라벨처럼 취급하면 안 됩니다.

### 5.2 관측 밀도·유효 양성 비율도 다름

| 로컬 역할 | n | 평균 관측 분/15 | 5분만 관측한 창 | 실제 share=0 비율 | target 평균 | target RMS | 상수0.1 RMSE |
|---|---:|---:|---:|---:|---:|---:|---:|
| selection | 1000 | 12.165 | 262 (26.2%) | 32.6% | 0.098867 | 0.183935 | 0.155109 |
| ensemble_fit | 500 | 10.898 | 196 (39.2%) | 40.0% | 0.097768 | 0.189016 | 0.161782 |
| ensemble_gate | 500 | 13.440 | 63 (12.6%) | 28.2% | 0.088037 | 0.168718 | 0.144424 |

Test는 기존 EDA에서 1,500×15분 중 결측734분, 평균 관측14.5107분입니다. 이는 라벨 없는 입력의 기술 통계입니다. 같은 합성법을 썼다고 관측 마스크와 배경 사이트 구성까지 같은 분포가 되는 것은 아닙니다.

명시적 no_source는 각 역할20%입니다. 그러나 부분 삽입·경계 통과·관측 마스크의 중첩 때문에 관측된 추가 에너지가0이 된 예제를 재추첨하지 않고 보존합니다. 따라서 실제 share=0 비율은20%와 다릅니다. 즉시 수식 오류라고 단정할 수는 없지만, mask가 추가 유무를 쉽게 예측하게 하는 인공적 상관이 생기는지 진단해야 합니다.

### 5.3 예측 분포는 기술 통계로만 해석

Test 예측share의 평균/RMS는 LightGBM5fold에서0.264153/0.325630, Fold0 전체5모델에서0.264744/0.326982입니다. Test의 실제 정답 분포가 아닙니다. 이를 임의의 '정상 RMS'로 강제로 줄이는 보정은 하지 않았습니다.

## 6. 확인된 문제와 아직 확정하지 못한 원인

확인됨:
1. 로컬 selection/fit/gate는 같은 합성 연산자 계열과 같은 참조509개를 공유합니다.
2. 현재 Fold0 평가 사이트·recorder는 TRAIN에도 있고, 관측 밀도도 기존 Test EDA와 다릅니다.
3. 낮은 로컬 RMSE·높은 AUC가 Public으로 전달되지 않아 검증의 대표성이 확보되지 않았습니다.
4. CSV의1,500ID·375열 순서, NaN,0.1dB처리, 완료 체크포인트, 물리 풀링, 가중 평균, 저장 시 float roundtrip, 배치 재현성을 검증했습니다. Fold0 전체 CSV의 배치 차이는 최대4.77e-7로 허용 범위 안입니다. 재현 가능한 단순 ID·열 순서·가중 평균 오류는 발견하지 못했습니다. 다만 비공개 생성기에 대한 의미·단위의 정확성까지 증명한 것은 아닙니다.
5. 이번에 미사용 report 정답을 열지 않았습니다. R9 신경망5Fold의 최종 OOF는 아직 측정하지 않았습니다.

유력하지만 미확정인 가설:
- 음원을 추가한 방법·세기·시간 위치·외부 녹음의 배경 및 장비 특성을 학습해 공식 Test 조건으로 전달되지 않았을 수 있습니다.
- 상대 특징에도 남아 있는 주파수 profile/w/mask로 같은 녹음기·결측 패턴을 식별했을 수 있습니다.
- vessel 참조에 포함된 ambient나 다른 외부 과도음과, 정답에 들어가는 passage 성분을 충분히 구분하지 못했을 수 있습니다.
- 회귀의 scale 오차와 진단 score의 구성·순위 실패가 별도로 존재할 수 있습니다.
- 특정 site/합성경로/유효 길이/고비율 꼬리가 전체 제곱오차를 지배할 수 있습니다.

## 7. GPU 재개 전에 수행할 진단 순서

우선1: 제출 경로와 단위 재점검.
- R9 best-window checkpoint를 CPU FP32로 selection에서 재현하고 저장 GPU BF16 예측과 ID별 비교합니다.
- 공개 starter minute_band_power와 현재 변환을 동일한 작은 입력으로 비교합니다. PSD 평균/대역 적분, 대역 정의, dB↔선형, minute 집계 순서, 결측, alpha 스케일 정의를 점검합니다.
- 이미 통과한 CSV·가중 평균 검산과, 아직 증명하지 못한 물리·생성기 동등성을 구분합니다.

우선2: 저장 예측으로 오차 분해.
- zero/positive, target 크기, 관측 분수, site/recorder, 참조 클래스·길이, inside/short/edge별 RMSE·AUC·bias·SSE 비중을 계산합니다.
- 잔차 Gram/covariance로 고정 가중치 MSE=w'Gw를 검산합니다. 로컬 평균화 악화가 편향과 오차 상관에서 오는지 분리합니다. Test의 오차 공분산은 숨겨진 정답 없이 계산할 수 없습니다.
- share 자체의 순위 AUC와 diagnostic score의 AUC도 분리해 score 구성만의 문제인지 확인합니다.

우선3: 새로운 교차 환경 평가를 사전 고정.
- 현재 미사용인 공개 domain 배경을 사용한 새 사이트·recorder 평가.
- 같은 B/A에서 native/minute/시간 배치 연산자를 바꾼 교차 생성기 평가.
- 원래 mask와 고밀도 관측 조건을 분리한 평가. mask 변경 시 관측 셀에 대한 q/y/w를 올바르게 재계산합니다.
- 공통 gain 변화에는 물리 비율의 불변성, 대역별 EQ에는 분모 가중치 변화에 따른 y 재계산을 확인합니다.
- 소수 참조나 비공개 Test 통계에 맞추기 전에, 어떤 미관측 조건에서 성능이 붕괴하는지 특정합니다.

우선4: 작은 CPU 모델로 대책을 비교한 후 GPU 재개.
- 원인을 좁힌 뒤 LightGBM 또는 작은 CNN으로 사전 고정 ablation을 수행합니다.
- 큰 모델·추가 epoch·나머지 Fold만 늘리면0.90 이상이 된다고 가정하지 않습니다.
